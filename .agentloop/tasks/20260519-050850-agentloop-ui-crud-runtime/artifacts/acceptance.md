# Acceptance Criteria

| ID | Required | Verification | Criterion | Status | Evidence |
| --- | --- | --- | --- | --- | --- |
| AC-1 | yes | functional test or browser smoke test | The UI provides a task list that reads existing AgentLoop tasks from `.agentloop/tasks`, shows each task's id, title, status, phase, iteration progress, updated time, and clearly indicates the current task when known. | pending | UI task list rendering with seeded task states |
| AC-2 | yes | functional test | A user can create a new task from the UI by entering a task request; creation uses AgentLoop's existing task start behavior and results in a new task directory with `state.json`, `analysis.md`, `acceptance.md`, and `acceptance.json`. | pending | Created task files and UI confirmation |
| AC-3 | yes | functional test or browser smoke test | A user can open a task detail view that shows the task request/title, status, current phase, iteration count, approval requirement, phase statuses, acceptance criteria, and available artifact links or previews. | pending | Detail view rendering for a task with artifacts |
| AC-4 | yes | functional test | A user can update supported per-task settings from the UI, at minimum `max_iterations` and `test_commands`, using existing AgentLoop config validation and persisting changes to the task's `config.json`. | pending | Updated `config.json` and reflected UI state |
| AC-5 | yes | functional test | A user can delete a task from the UI after explicit confirmation; the task disappears from the list and its task directory is removed using the same safety boundaries as existing task deletion behavior. | pending | Deleted task no longer listed and directory removed |
| AC-6 | yes | functional test | The UI exposes valid lifecycle actions for the selected task, including approve when waiting for alignment, cancel when cancellable, and run/resume when ready, while disabling or explaining invalid actions based on current status. | pending | Status-specific action availability and state transitions |
| AC-7 | yes | functional test or browser smoke test | The UI shows the latest task progress after lifecycle actions by refreshing persisted state fields, including status, current phase, phase statuses, iteration/max iteration, and acceptance criteria statuses. | pending | State change visible after approve/run/cancel |
| AC-8 | yes | functional test | The UI shows runtime return information for the latest relevant iteration, including role, runtime, command when available, exit code, duration when available, produced artifacts, and readable stdout/stderr log content or clear missing-log messages. | pending | Latest `state.agents` entries and runtime log display |
| AC-9 | yes | functional test | The UI shows local test command output for the latest iteration when present, including command, exit code, duration, and log content from `.agentloop/runs/<task_id>/<iteration>/tests/`. | pending | Test log display for a task with configured tests |
| AC-10 | yes | review and functional test | The implementation handles missing or malformed task files, missing artifacts, empty runtime logs, and long logs without crashing; long log content is bounded in the UI. | pending | Error/empty-state cases covered by test or manual verification |
| AC-11 | yes | automated tests | Core task UI data-loading and mutation paths are covered by tests that use temporary workspaces and do not depend on a user's real `.agentloop` data. | pending | Test suite output |
| AC-12 | yes | manual review | The UI is task-management first: first screen is the usable task console, not a marketing page, and it uses clear controls for task CRUD, lifecycle actions, progress, and runtime output. | pending | Manual UI review |
